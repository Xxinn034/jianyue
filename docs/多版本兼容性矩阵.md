# 简阅 · 多版本兼容性矩阵（2026-10-05 实测）

本文只记录**我们自己跑出来的数据**，不引用文档结论。每条都有设备、命令和落盘证据。

## 一、结论先讲

1. **结论（2026-10-05 更新）：现在构建出的 APK 带 `targetSdkVersion=28` + `usesCleartextTraffic=true`，在四个平台上都实测通过** ——
   Android 1.0（API 1）、Android 4.1.2（API 16）、Android 11 真机（API 30，vivo V2073A/PD2073）、Android 17（API 37，16KB 页）。
   Android 14+ 不再拦安装，也不需要 bypass。
2. **这两个字段是构建后二进制补丁写进 APK 的**，不是改工具链：`tools\axml-patch.ps1` 在编译产物里给 `<uses-sdk>` 插一个属性、给 `<application>` 插一个布尔属性，并同步补 XML resource-map。
   之所以必须这么绕：aapt v0.2（2008）用的 API-1 `android.jar` 资源表里**根本没有** `targetSdkVersion` 这个属性（`No resource identifier found ...`），
   而把 `-I` 换成新版 `android.jar` 它也读不了（`Bad string block: last string is not 0-terminated`）。
   补丁只动 manifest 的这两个属性，资源表 / dex / 签名链路完全不变，所以 Android 1.0 上的行为一字未改（34/34 全过）。
3. **取值 28 是量出来的，不是猜的**：安装门槛实测原文
   `INSTALL_FAILED_DEPRECATED_SDK_VERSION: App package must target at least SDK version 24, but found 1` → 必须 ≥24；
   Android 17 上 `targetSdk=24/26` 会弹系统框 `DeprecatedTargetSdkVersionDialog`（"This app was built for an older version of Android…"），`28/29/30` 不弹；
   而 `targetSdk=29` 上 **分区存储** 生效，实测同样的 `importPath` 直接报 `读不到文件`（即使已授权）→ 上限压到 28。
   `usesCleartextTraffic` 是 targetSdk ≥ 28 的代价：Android 9+ 默认禁明文 HTTP，而书源全是 HTTP；实测在 29 上不开这个开关搜索请求一条都发不出去。
4. **运行时权限是必须补的**（targetSdk ≥ 23）：新系统上书源导入最初报 `读不到文件：/sdcard/sources.json`，`pm grant` 后就成功。
   现在由 `src/com/jianyue/reader/util/Compat.java` 统一申请（编译期只有 API-1 符号，所以全程反射；旧系统自动短路成"已授权"）。
   实测真机 Android 11 上走的是系统对话框「"简阅"请求存储权限，是否允许？→允许」→ 点完自动续跑被中断的导入。
5. **装上不等于能起**（历史记录，bypass 路线的教训）：bypass 装上后第一次启动会被
   `com.google.android.permissioncontroller/.permission.ui.ReviewPermissionsActivity`（老应用权限复核页）接管，应用进程根本没起来 —— 所以抬 targetSdk 不是可选项，是唯一正路。
6. 兼容性是**单向**的：能在老版本跑推不出能在新版本跑（新框架只会加严，这次 API 16 的 keyguard、API 21 的 `checkForRelayout` NPE、API 37 的 targetSdk 门槛与分区存储都是同一个道理）；反向基本成立。

## 三、数据点：Android 4.1.2（API 16，AVD Nexus_4，x86，768x1280 @320dpi）

- 设备指纹：`sys.boot_completed=1`，`ro.build.version.sdk=16`，`release=4.1.2`，`abi=x86`。
- 验收：`tools\verify-api16.ps1`（脚本按 API 1 那套宿主驱动 intent 复刻，外加 `screencap`/`uiautomator`）
  **31 项全过，0 失败**：6 个 Activity 全部 `Displayed` 且无 crash；书源导入 `added=1 updated=0 failed=0`；
  搜索 `search/book?keyword=斗罗大陆... -> HTTP 200 9298B`、`1 hits, 1 books after merge`；
  详情 `engine.info` + `engine.toc -> 1184 chapters`；正文 `engine.content -> 2465 chars`、`reader: paginated chars=... pages=...`；
  25sp 也过：`reader: cut page 1 budget=16 chars=249 measured=16`。
- **渲染证据（这台机器 screencap 是坏的，所以用视图树）**：headless 下 `-gpu swiftshader_indirect` 与 `-gpu guest`
  两种模式的 `screencap` 都只返回整屏同色的 3906 字节 PNG，不可信。改用 `uiautomator dump` 拿到真实控件与坐标：
  - 阅读页只有一个文本节点 `[[0,0][384,581]] len=207 cjk=148`，内容是「第二章 被饲养的人类 / 作者：唐家三少 本章字数：2369…」；

  - App 表面是 **384x640（物理 768x1280 的 1/2）**，即 Android 4+ 的 legacy screen compat mode 生效——和真机 SHL25 的 320x526 是同一种机制。
- 环境差异记录：`tls: supported protocols = SSLv3 TLSv1 TLSv1.1 TLSv1.2`（API 1 只有 `SSLv3 TLSv1`）；`rhino=ready` 正常。

- 证据文件：`G:\jianyue-src\tools\api16\`（`verify-api16.txt`、`visual-api16.txt`、`shelf2.xml`、`reader2.xml`、`*.png`）。

## 四、数据点：Android 17（API 37，google_apis_ps16k x86_64，16KB 页）

- AVD 是**手写**出来的：本机只有 Java 8，`cmdline-tools\latest\bin\avdmanager.bat` 直接报
  `Java version 17 or higher is required`，跳过版本检查后是 `UnsupportedClassVersionError (class file version 61.0)`。
  于是手工建 `~\.android\avd\api37.ini` + `api37.avd\config.ini`（`image.sysdir.1=system-images\android-37.1\google_apis_ps16k\x86_64\`，skin pixel_6），emulator 36.6.11 能正常认。
- 设备指纹：`release=17`、`api=37`、`codename=REL`、`getconf PAGE_SIZE=16384`、
  `ro.build.fingerprint=google/sdk_gphone16k_x86_64/emu64xa16k:17/CP31.260623.005/15817740:userdebug/dev-keys`。
- **A) 普通安装（实测原文）**：
  ```
  Performing Streamed Install
  Failure [INSTALL_FAILED_DEPRECATED_SDK_VERSION: App package must target at least SDK version 24, but found 1]
  ```
- **B) 加 bypass**：`adb install -r --bypass-low-target-sdk-block` → `Success`；
  `dumpsys package` 读出 `minSdk=1 targetSdk=1 versionCode=0`。
- **C) 装上之后起了吗？没有**：
  - `am start -W -n com.jianyue.reader/.ui.MainActivity` → `Status: ok`，但
    `Activity: com.google.android.permissioncontroller/com.android.permissioncontroller.permission.ui.ReviewPermissionsActivity`；
  - `dumpsys activity activities` → `topResumedActivity=...ReviewPermissionsActivity`；
  - 我们的进程 `ps -A | grep jianyue` 为空，`logcat -s JianYue:*` 一行都没有（应用确实没被启动过）。
  - 也就是说：**targetSdk<23 的老应用在新系统上第一次运行会被"权限复核页"接管**，用户点完才轮到应用自己。
- **D) 没能验的部分（如实记录）**：这台 16KB 页镜像在软件渲染下慢到自己的 system_server 反复 ANR
  （`E ActivityManager: ANR in system ... NotificationHistoryJobService, waited 72837ms`、弹「Process system isn't responding」），
  首次开机 dex2oat 单包就花了 115s、整机开机约 20 分钟。所以"点了权限复核页之后应用能不能正常跑"这次**没有测出来**，
  不作为结论，只标注为未验项。
- 证据文件：`G:\jianyue-src\tools\api37\`（`install-block.txt`、`mainactivity.log`、`perm.xml`）。

### 四之二、同一台 Android 17：改造后（2026-10-05）

- **普通安装成功**（无 bypass）：`dumpsys package` → `versionCode=10000 minSdk=1 targetSdk=28`；启动后焦点直接是 `MainActivity`，**没有** `DeprecatedTargetSdkVersionDialog`。
- **权限**：`SourcesActivity -e importPath /sdcard/sources.json` → 日志 `compat: asking for the storage permission (sdk=37)` → 系统框 "Allow 简阅 to access photos, videos, music, audio, and other files…" → `uiautomator` 点 Allow → `importPath result: added=5 updated=0 failed=0 error=null`。
- **搜索**：`engine.searchAll sources=5 threads=4 books=47` → `search done: 47 hits, 21 books after merge, failures=0`（5 个书源全是 HTTP，cleartext 开关生效）。
- **详情/目录/正文**：`engine.toc -> 395 chapters`、`engine.content 公告（更新时间） -> 330 chars`、`reader: paginated chars=352 pages=1 viewW=986 viewH=2167 linesPerPage=22`；截图 `tools\preview\a17-reader.png` 排版正常（标题置顶、每段空两格）。
- **本地导入**：`MainActivity -e importBook /sdcard/novel-utf8.txt` → `local: imported ... format=txt chapters=13` → 书架 1 本 → 自动进阅读页 `local chapter=0 ... chars=653 pages=2`。
- 结论：**Android 17 上功能全链路可用**，与 API 1 / API 16 同一份 APK。

## 五、数据点：Android 11 真机（vivo V2073A / PD2073，API 30）

- 设备：`3051015388005DF`，`ro.build.version.sdk=30`、`release=11`、`arm64-v8a`、1080x2408 @480dpi。
- **完全按普通用户路径装**（先 `uninstall`，再 `adb install`）：会弹 vivo 的安装确认页
  （`com.android.packageinstaller/PackageInstallerActivity`：勾"已了解应用的风险检测结果"→"继续安装"），
  这是 ROM 行为不是应用问题；确认后 `pm list packages` 出现 `com.jianyue.reader`，`targetSdk=28`。
  **坑**：这台机器屏幕锁着时 `adb install` 直接返回 `INSTALL_FAILED_ABORTED: User rejected permissions` —— 必须先唤醒解锁再装。
- **权限**：启动 `SourcesActivity -e importPath ...` 后弹系统框「"简阅"请求存储权限，是否允许？」→ 点"允许"→ 导入续跑成功，
  `dumpsys package` 显示 `READ_EXTERNAL_STORAGE: granted=true, flags=[USER_SET|...]`（USER_SET = 用户对话框授权，不是 adb grant）。
- **功能**：书源页 `5 个`（纵横/阅友/新笔趣阁/黑岩/猫九）；搜索 `找到 21 本（47 个来源）`，与 Android 17 完全一致；阅读页正文渲染正常（`公告（更新时间）…`）。
- **坑**：这台机器的 `adb shell screencap` **永远返回 0 字节**（`/sdcard` 与 `/data/local/tmp` 都一样），所以真机取证只能靠 `uiautomator dump` + `dumpsys`；
  另外它的 `logcat -s JianYue:*` 也拿不到应用日志，功能验证要靠 UI 树。

## 六、改造已落地（2026-10-05）：做法、取值依据与副作用

1. **构建链写 targetSdk** → 已实现，产物是 `tools\axml-patch.ps1`（PowerShell，本地与 CI 同一份，不引入 Python 依赖）。
   `build-reader.ps1` 第 **6/8** 步在 dex 注入之后、zipalign/签名之前调用它；第 **8/8** 步会 `aapt dump xmltree` 断言 `0x01010270` 的值真是 `0x1c`，
   补丁失效会让构建直接失败（这是唯一一类"只在装的时候才炸、本地看不出来"的回归）。
2. **运行时权限** → 已实现：`src/com/jianyue/reader/util/Compat.java` 是**唯一入口**。编译期只有 API-1 符号，所以 `SDK_INT` / `checkSelfPermission` / `requestPermissions` 全部反射调用；
   API < 23 直接短路成"已授权"。三个调用点：`MainActivity`（宿主 `-e importBook`）、`SourcesActivity`（宿主 `-e importPath`）、`FilePickerActivity`（UI 的"从文件导入"）。
   被权限对话框打断的操作会**挂起再重放**（`onRequestPermissionsResult` 故意不写 `@Override`、不调 `super`：API-1 的 android.jar 里没有这个父方法）。
3. **副作用（实测，已确认无害）**：`targetSdk ≥ 4` 之后，老设备**不再套 legacy 屏幕兼容模式**。
   改造前 API 16 上 App 表面是 `384x640`（物理 768x1280 被拉伸），现在 dump 出来是 `768x1184` 真身，阅读页文本节点 `[0,0][768,1164]`。
   也就是说内容以原生密度渲染、物理字号不变、一屏信息更多。书架（搜索框/放大镜/书名行都在界内）与阅读页都实测正常，API 1 的 34 项也全过。
4. **取值区间** → 实测后定为 **28**：`24/26` 会被 Android 17 弹 `DeprecatedTargetSdkVersionDialog`，`29` 起强制分区存储（`importPath` 直接 `读不到文件`），
   而 28 的代价只有一条 —— 必须在 `<application>` 上加 `usesCleartextTraffic="true"`（书源全是 HTTP），同一个补丁一起加。
5. **仍待办**：Android 14+ 上首次安装时 vivo/各家 ROM 的"未知来源"安装确认页需要用户点一下（这是系统行为，不是应用问题）；
   Android 13+ 上给普通用户的提示文案仍是"读不到文件"，可以改成"没有存储权限"（当前只对新路径做了这个提示）。

. .\secrets.local.ps1
& .\build-reader.ps1                     # -> out\reader.apk（targetSdkVersion : 28 (manifest attribute stamped)）

# 1) Android 1.0：34 项全链路

$adb = 'C:\Users\LX\AppData\Local\Android\Sdk\platform-tools\adb.exe'
